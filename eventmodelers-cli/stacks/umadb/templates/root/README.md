# UmaDB Quickstart

A minimal Spring Boot project wired up to [UmaDB](https://umadb.io/) - a gRPC event store - via
its Java client, ready for the `build-state-change`/`build-state-view`/`build-automation` skills
to generate slices into.

## Prerequisites

- Java 21 or higher
- Maven 3.6 or higher
- Docker (for running UmaDB and PostgreSQL locally)

## Getting Started

```bash
docker-compose up -d
mvn spring-boot:run
```

Or run `QuickstartApplication` from your IDE. `spring-boot-docker-compose` also starts
`docker-compose.yml`'s services automatically on `mvn spring-boot:run` if they aren't running yet.

## What's here

- `UmaDbConfig` - wires the shared `UmaDbClient` bean every command handler's `DecisionModelLoader`
  uses (UmaDB has no Spring Boot starter of its own, unlike Axon Framework - this project connects
  and shuts it down by hand).
- `eventstore/` - the shared plumbing every slice builds on, since the raw UmaDB client has no
  framework layer of its own:
  - `EventCodec` - JSON (Jackson) serialization of domain event/command records to/from UmaDB's
    opaque `byte[]` payload.
  - `DecisionModelLoader` - the read-decide-append loop every write slice's command handler uses;
    see `build-state-change`.
  - `SliceEventListener` / `EventDispatcher` - the live-subscription fan-out every read-model
    projector and automation processor reacts through; see `build-state-view` / `build-automation`.
  - `OptimisticConcurrencyException` - thrown when a command handler's append is rejected by a
    conflicting concurrent write.
- `src/test/java/.../testsupport/InMemoryUmaDbClient` - a fast, in-process fake of `UmaDbClient`
  for command-handler unit tests, since UmaDB ships no test-fixture library of its own (only a
  Testcontainers-based real-server setup, which is what `build-state-view`'s reference
  integration test uses instead).

No slices are included - each is generated by the matching build skill from a board's `slice.json`.
